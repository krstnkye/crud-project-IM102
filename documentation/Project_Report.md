## 2. Introduction

The Product Inventory Management System is a desktop application that helps users record and manage product information. Many small inventory tasks become difficult when records are written manually because products can be misplaced, quantities may be miscalculated, and old records may not be updated properly.

This project solves that problem by using a graphical interface where users can add, view, update, and delete product records. The system stores data in an SQLite database so the records remain available even after the program is closed and reopened.

## 3. Project Objectives

General Objective:

To develop a simple inventory management system that demonstrates complete CRUD operations using Python, Tkinter, and SQLite.

Specific Objectives:

- Create a user-friendly product entry form.
- Save product records in an SQLite database.
- Display product records in a table.
- Allow users to update selected product records.
- Allow users to delete selected product records with confirmation.
- Automatically calculate total products, total stock units, and low-stock products.
- Validate invalid input and show clear pop-up messages.

## 4. Functional Requirements

The system must allow users to:

- Add a product with product name, category, quantity, and unit price.
- View all saved products in the inventory table.
- Select an existing product and update its details.
- Delete a selected product after confirmation.
- Clear the input fields.
- See automatically updated dashboard totals after each operation.
- Receive error messages when invalid input is entered.

## 8. Flowchart and Algorithm

The system starts by opening the application, loading the database, and displaying the current inventory records and dashboard totals. The user then selects whether to add, update, delete, or exit.

Flowchart source is saved in `documentation/flowchart.mmd`.

### Add Product Algorithm

1. User enters product name, category, quantity, and unit price.
2. System checks that all required fields contain valid information.
3. If input is invalid, an error message appears.
4. If input is valid, the new product is inserted into SQLite.
5. The product table and inventory totals are refreshed.
6. A success message is displayed.

### Read Product Algorithm

1. System opens the SQLite database.
2. System retrieves all product records from the `products` table.
3. Retrieved records are displayed in the table.
4. Dashboard totals are calculated from the current records.

### Update Product Algorithm

1. User selects a product from the table.
2. Product details are loaded into the entry form.
3. User edits the product information.
4. System validates the new values.
5. If input is invalid, an error message appears.
6. If input is valid, SQLite updates the selected product record.
7. The table and dashboard totals are refreshed.
8. A success message is displayed.

### Delete Product Algorithm

1. User selects a product from the table.
2. User clicks the Delete Product button.
3. System asks for delete confirmation.
4. If the user cancels, no record is removed.
5. If the user confirms, SQLite deletes the selected product record.
6. The table and dashboard totals are refreshed.
7. A success message is displayed.

## 9. Exception Handling Plan

| Error Condition | Expected Pop-up Message |
| --- | --- |
| Empty product name | "Please enter a product name." |
| Quantity contains letters | "Quantity must be a whole number." |
| Negative quantity | "Quantity cannot be negative." |
| Invalid price | "Please enter a valid price." |
| Update without selecting | "Please select a product to update." |
| Delete without selecting | "Please select a product to delete." |
| Delete confirmation | "Are you sure you want to delete this product?" |
| Database error | "Unable to save changes. Please try again." |
